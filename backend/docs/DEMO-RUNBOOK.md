## Что требует интернета

| Часть | Без интернета |
|---|---|
| Сайт/приложение → backend | нужен Funnel (интернет на ноутбуке) |
| Ответы, детали, фото, проверка утверждений | нет: это Gemini (Google) |
| Проверка цены на сайте | нет: читает сайт поставщика |
| OCR сканов, прайс из файла, ведомость, Excel | работают локально, но приложению всё равно нужен доступ к backend |

Без интернета на ноутбуке демонстрация вживую невозможна. Плохой интернет замедлит шаги с Gemini (обычно 3–15 с).

## Резервный план

1. **Основной:** ноутбук на зарядке, крышка закрыта/открыта — не важно (сон отключён), Funnel `https://win-347ek05mdnv.tailf14622.ts.net`.
2. **Интернет на месте плохой:** раздать интернет на ноутбук с телефона (точка доступа). Funnel восстановится сам, адрес не меняется.
3. **Funnel не отвечает:** проверить `tailscale funnel status`; перезапустить Tailscale. Запасной туннель — Cloudflare quick tunnel (`cloudflared tunnel --url http://127.0.0.1:8022`), но адрес у него каждый раз новый: приложению нужен способ сменить адрес backend (см. «Постоянный адрес API» ниже). CORS_ORIGINS менять не нужно — там адреса приложений (Vercel, `https://localhost`, `capacitor://localhost`), а не адрес backend. Запускает Ерасыл.
4. **Сломалось новое:** откат на стабильную сборку `ba8b4ed` — отдельная копия `C:\Users\user\wt\stable`, перезапуск ~1 минута.
5. **Gemini недоступен или кончилась квота:** живой показ ИИ-шагов невозможен; показываем заранее сохранённые результаты (`eval/results/demo_*.json`, `.xlsx`) и запись экрана.
6. **Последний рубеж:** видеозапись полного сценария с телефона — снять заранее, пока всё работает.

Надёжнее всего — VPS: backend не зависит от ноутбука и Wi-Fi на площадке.

## Постоянный адрес API (чтобы не пересобирать приложения)

- Адрес Funnel `https://win-347ek05mdnv.tailf14622.ts.net` постоянный: он не меняется при перезапуске backend, Tailscale,
  смене сети или после сна ноутбука. Меняется только при переименовании компьютера в Tailscale или выходе из tailnet.
- Меняется адрес только у запасного туннеля Cloudflare. Варианты без пересборки APK/PWA:
  1. **Адрес backend из файла конфигурации (рекомендую).** Приложение при старте читает маленький JSON с постоянного
     адреса (например, `https://doc-mind-ai-liart.vercel.app/backend.json` → `{"apiBaseUrl": "https://..."}`), а
     если файл недоступен — берёт встроенный `VITE_API_BASE_URL`. Сменить backend = поменять один файл на Vercel.
     Это работа frontend (Samir), backend и API не меняются.
  2. Прокси через Vercel (rewrites `/api/*` → backend): приложение ходит на адрес Vercel. Не проверено: лимиты Vercel
     на размер загрузки и время ответа для внешних rewrites; Preview-адреса закрыты Deployment Protection.
  3. Свой домен (VPS или именованный туннель Cloudflare) — постоянный `api.<домен>`; нужен купленный домен.

## Перед публичным тестом по QR (проверено 08.11.2026 на 8022)

- Лимиты: на сессию 12 AI-запросов/мин и 40 в сутки; на один IP 300 в сутки; на весь сервер 1000 в сутки. Загрузки
  6/мин, до 10 документов и 100 МБ на сессию, файл до 20 МБ. Новые сессии — 30/мин с одного IP.
  Funnel передаёт реальный IP (в базе разные клиенты), поэтому лимит на IP работает для каждого человека. Но на
  площадке все в одном Wi-Fi могут выходить с одного IP — тогда 300 в сутки на всех.
- Аварийный выключатель ИИ: перезапуск с `AI_EMERGENCY_STOP=1` — все AI-запросы получают 429, остальное работает.
- Ключ Gemini только на сервере (`backend/.env`, в git не попадает). Во всех ветках репозитория и их истории ключа нет;
  во frontend только `VITE_API_BASE_URL` и `VITE_TELEGRAM_BOT_URL`, а `deployEnv` запрещает секреты в `VITE_*`.
- Чужие данные по ID: вторая сессия получила 404 на документ, файл, страницу, текст, факты, детали, удаление,
  чат, сообщения, проверку утверждения, прайс; в своих списках чужого не видит; без токена — 401.
